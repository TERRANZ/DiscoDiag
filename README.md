# DiscoDiag

**DiscoDiag** — кроссплатформенное десктопное приложение для диагностики автомобиля **Land Rover Range Rover L322 (5.0 supercharged, 2010+)** через OBD2 интерфейс. Программа подключается к ЭБУ автомобиля по Bluetooth (RFCOMM) и отображает в реальном времени данные с датчиков температуры, давления и уровня жидкостей в виде приборной панели.

## Возможности

- **Подключение по Bluetooth** — сканирование доступных Bluetooth-адаптеров и сервисов с последующим установлением RFCOMM-соединения с ЭБУ автомобиля.
- **Инициализация OBD2** — автоматическая последовательность инициализации: сброс ЭБУ (`ATZ`), включение заголовков ответов (`ATH1`), выбор протокола (`ATSP6`).
- **Непрерывный мониторинг** — циклический опрос датчиков с задержкой `QTimer` между командами; Bluetooth-сокет работает асинхронно, поэтому интерфейс не блокируется.
- **Приборная панель** — отображение показаний в виде LCD-индикаторов и поворотных циферблатов (QDial).
- **Модульная архитектура команд** — паттерн Command позволяет легко добавлять новые диагностические команды.
- **Логирование** — вывод отладочной информации в консоль и файл `debug.log`.
- **Локализация** — исходные строки интерфейса написаны на русском языке; каталог Qt Linguist подключён и загружается из `:/i18n`, но готовый английский перевод пока не заполнен.

## Архитектура

Приложение построено по слоистой событийно-управляемой архитектуре с четким разделением ответственности.

### Слои приложения

```
┌─────────────────────────────────────────────────────┐
│                    UI Layer                         │  (src/ui/)
│        MainWindow, RemoteSelector, *.ui             │
├─────────────────────────────────────────────────────┤
│                Bluetooth Layer                      │  (src/bt/)
│                    BtBackend                        │
├─────────────────────────────────────────────────────┤
│                  OBD Layer                          │  (src/obd/)
│              ObdService, ObdParser                  │
├─────────────────────────────────────────────────────┤
│               Command Layer                         │  (src/command/)
│         AbstractCommand + implementations           │
└─────────────────────────────────────────────────────┘
```

### Поток данных

```
Пользователь нажимает "Запуск..."
              │
              ▼
  MainWindow::on_action_start_triggered()
              │
              ▼
    ObdService::startService(address)
              │
              ├──→ BtBackend::listAdapters()  (проверка Bluetooth)
              │
              ▼
    BtBackend::startClient()
              │  QBluetoothSocket → адрес из настроек (по умолчанию
              │  10:21:3E:4A:3E:41), RFCOMM/SPP
              ▼
    ObdService::connected()  [Состояние: CONNECTED]
              │
              ▼
    Последовательность инициализации:
    ┌──────────────────────────────────────────────────────────────┐
    │ 1. ATZ   (ObdResetFixCommandImpl)       CONNECTED→RESETTED   │
    │ 2. ATH1  (DisplayHeaderCommandImpl)     RESETTED→DEV_CONFIG  │
    │ 3. ATSP6 (SelectProtocolObdCommandImpl) DEV_CONFIG→INWORK    │
    └──────────────────────────────────────────────────────────────┘
              │
              ▼
    sendNextCommand()  [Состояние: INWORK]
              │
              │  Циклический опрос (круговая очередь):
              │  22F405 → 2203F3 → 221E69 → 22D11A → 22F446 → 22F40F
              │  → 22D11C → 221E8A → 2203E6 → 2203F2 → 22F423
              │  → 222B0D → 22F42F → (повтор)
              │  Между командами — одноразовый QTimer / 100 мс.
              ▼
    Обработка ответа:
    - BtBackend режет поток по '>' на отдельные кадры
    - ObdParser нормализует пробелы и находит маркер 0x62
    - Command::calculate() преобразует байты в значение
    - ObdService формирует ObdResult и emit updateUI(result)
              │
              ▼
    MainWindow::update_ui(result)
              │
              ├──→ teDebug: append (сырой ответ и значение)
              ├──→ QLCDNumber + QDial для всех опрашиваемых датчиков
              └──→ статусная строка / сообщения об ошибках
```

`ObdService` и принадлежащий ему `BtBackend` живут в отдельном рабочем
потоке (`QThread`) и общаются с UI через queued-сигналы. `QBluetoothSocket`
неблокирующий, поэтому рабочий поток простаивает между ответами; задержка
между командами реализована одноразовым `QTimer` (100 мс) в том же потоке.

### Конечный автомат OBD-сервиса

```
NC (0)
  │ startService(address)
  ▼
DEV_SELECTED (1)
  │ QBluetoothSocket::connected
  ▼
CONNECTED (3) ──ATZ──→ RESETTED (4) ──ATH1──→ DEV_CONFIG (2)
                                                    │
                                                 ATSP6
                                                    ▼
                                               INWORK (6)
                                                    │
                              QTimer / ответы датчиков
                                                    │
                          ┌─────────────────────────┘
                          ▼
                ERROR (-1) ← ошибка сокета/адаптера,
                              обрыв соединения или
                              отклонённая команда
```

`stopService()` из любого состояния возвращает в `NC`. После `ERROR`
повторный `startService()` перезапускает сессию.

## Диагностические команды

### Паттерн Command

Все OBD-команды наследуются от абстрактного класса `AbstractCommand`:

```cpp
class AbstractCommand {
    QString  m_cmdId;      // OBD2-идентификатор команды (например "22F405")
    QString  m_cmdName;    // Человеко-читаемое имя команды
    QString  m_rawData;    // Сырые данные ответа

    virtual int calculate(const QString &value) const;
    // По умолчанию возвращает -1; переопределяется в подклассах
    // для преобразования сырых hex-данных в осмысленное значение
};
```

### Общие OBD2 AT-команды

| Класс | Команда | Назначение |
|---|---|---|
| `ObdResetFixCommandImpl` | `ATZ` | Сброс ЭБУ / OBD-адаптера |
| `DisplayHeaderCommandImpl` | `ATH1` | Включение заголовков в ответах (ЭБУ будет prepend'ить ID команды) |
| `SelectProtocolObdCommandImpl` | `ATSP6` | Протокол 6: ISO 15765-4 CAN, 11-битный ID, 500 кбит/с |
| `ExtParamsCommandImpl` | *(пусто)* | Расширенные параметры (заглушка, не реализована) |

### Команды датчиков автомобиля (LR322)

**Температура** — все используют одинаковую формулу `A - 40` (стандарт OBD2 для температуры в °C):

| Класс | Команда | Датчик |
|---|---|---|
| `CoolantTempCommandImpl` | `22F405` | Охлаждающая жидкость |
| `OilTempCommandImpl` | `2203F3` | Масло двигателя |
| `GbTempCommandImpl` | `221E69` | Коробка передач |
| `TCTempCommandImpl` | `22D11C` | Раздаточная коробка |
| `RDTempCommandImpl` | `221E8A` | Задний дифференциал |
| `ComprTempCommandImpl` | `22D11A` | Компрессор |
| `IntakeAirTempCommandImpl` | `22F40F` | Воздух на впуске |
| `AmbientAirTempCommandImpl` | `22F446` | Наружный воздух |

**Давление и уровень:**

| Класс | Команда | Датчик | Формула |
|---|---|---|---|
| `FuelPressCommandImpl` | `22F423` | Давление топлива | `(A × 256 + B) / 100` |
| `BrakePressCommandImpl` | `222B0D` | Тормозная система | `A × 8533.3337 + B × 33.33` |
| `FuelLevelCommandImpl` | `22F42F` | Уровень топлива | `(A × 100) / 255` (литры) |
| `OilLevelCommandImpl` | `2203E6` | Уровень масла | `A` |
| `OilVolumeCommandImpl` | `2203F2` | Объём масла | `A / 10` |

## Протокол общения с ЭБУ

### Подключение

| Параметр | Значение |
|---|---|
| **Протокол** | RFCOMM (Serial Port Service Class UUID) |
| **Адрес Bluetooth** | `10:21:3E:4A:3E:41` по умолчанию; меняется в «Настройка → Настройки приложения...» и сохраняется в `QSettings` |
| **Терминатор команды** | `\r` (возврат каретки) |
| **Терминатор ответа** | `>` (знак больше) |

### Формат ответа

Ответ ELM327 может содержать эхо команды, строку заголовка ЭБУ, переводы
строк (`\r`) и терминатор `>`. `BtBackend` режет входящий поток по `>`, а
`ObdParser` нормализует пробелы. Пример ответа на запрос `22F405`:

```
22F405            ← эхо команды (при ATE1)
7E8 04 62 F4 05 5C
│   │  │  │  │  └── Байт данных A (сырое значение датчика)
│   │  │  │  └───── Младший байт PID
│   │  │  └──────── Старший байт PID
│   │  └─────────── SID 0x62 (положительный ответ на mode 22)
│   └────────────── Количество данных байт
└────────────────── Идентификатор ЭБУ (ECU identifier)
```

Парсер не опирается на абсолютные позиции токенов: он находит маркер `62`,
пропускает два байта PID и берёт следующий байт как `A` (и следующий за ним
как `B`). Это работает и при включённом, и при выключенном эхе, а также с
заголовками `ATH1`.

### Парсинг ответов

Класс `ObdParser` предоставляет статические методы:

| Метод | Описание |
|---|---|
| `A(const QString &data)` | Первый байт данных после `62 <PID hi> <PID lo>` |
| `B(const QString &data)` | Второй байт данных после `62 <PID hi> <PID lo>` |
| `getIntAtPos(data, pos)` | Извлечение hex-значения по позиции с проверкой границ |
| `extractCommandId(data)` | ID команды из первого непустого токена |
| `hasPayload(data)` | Проверка наличия положительного ответа `62` и данных |

## Установка и сборка

### Требования

- **C++17** (GCC 9+, Clang 10+, MSVC 2019+)
- **Qt 6.2+** (модули: Core, Widgets, Bluetooth, LinguistTools; для тестов — Test)
- **CMake 3.16+**
- **BlueZ** (на Linux) — стек Bluetooth

### Локальная сборка

```bash
# Клонирование репозитория
git clone <repository-url>
cd DiscoDiag

# Конфигурация и сборка
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"

# Тесты
ctest --test-dir build --output-on-failure
```

Сборка в контейнере из `builder/Dockerfile`:

```bash
podman build -t discodiag-build builder
podman run --rm -v "$PWD:/src:Z" -w /src discodiag-build \
    bash -lc 'cmake -S . -B build && cmake --build build -j"$(nproc)" && ctest --test-dir build --output-on-failure'
```

## Использование

### Запуск

```bash
./build/DiscoDiag
```

При запуске создаётся файл `debug.log` в рабочей директории, в который записывается отладочная информация.

### Интерфейс

Меню приложения:

| Меню | Действия |
|---|---|
| **Диагностика** | `Запуск...` — начать опрос датчиков, `Остановка` — остановить опрос, `Выход` — закрыть приложение |
| **Настройка** | `Настройки приложения...` — открыть диалог выбора Bluetooth-устройства |
| **Помощь** | `О программе...` — показать информацию о приложении |

### Приборная панель

Приборная панель разделена на три вкладки.

**Вкладка «Основное»:**

Первый ряд — основные температуры:
- Температура охлаждающей жидкости
- Температура наружного воздуха
- Температура на впуске
- Температура масла
- Температура коробки передач

Второй ряд — дополнительные параметры:
- Температура заднего дифференциала (ЗД)
- Температура раздаточной коробки
- Температура компрессора
- Уровень масла
- Давление масла — виджет есть, но команда давления масла пока не реализована

Третий ряд — давление и топливо:
- Давление топлива
- Давление тормозной системы
- Уровень топлива в литрах

**Вкладка «Двигатель»:**
- Скорость автомобиля
- Наддув
- Абсолютное давление во впускном коллекторе
- Магистральное давление
- Массовый расход воздуха (MAF)
- Общий пробег
- Продольное ускорение
- Напряжение датчика раздаточной коробки
- Напряжение блока управления ABS
- Состояние блокировки заднего дифференциала

**Вкладка «Шасси»:**
- Скорости колёс по датчикам ABS (FL, FR, RL, RR)
- Высота подвески по всем четырём углам (FL, FR, RL, RR)

Большинство параметров отображается одновременно на циферблате (QDial) и
цифровом индикаторе (QLCDNumber). Для уровня масла циферблат имеет диапазон
0…255 (сырое значение датчика), для уровня топлива — 0…105 л. Пробег и
состояние блокировки дифференциала выводятся без циферблата.

Внизу расположена текстовая область для отладки (`teDebug`), отображающая сырые OBD-ответы.

## CI/CD

### GitLab CI Pipeline

Проект использует GitLab CI для автоматической сборки и запуска тестов.

```yaml
image: 192.168.3.1:5000/vterranz/discobuild

stages:
  - build
  - test
  - pr_agent

build:
  stage: build
  script:
    - cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    - cmake --build build -j"$(nproc)"
  artifacts:
    paths:
      - build

test:
  stage: test
  needs: [build]
  script:
    - ctest --test-dir build --output-on-failure
```

### Docker-сборщик

Docker-образ для сборки находится в `builder/Dockerfile` (Debian bookworm):

- `build-essential`, `cmake`, `ninja-build`, `pkg-config`
- Qt 6: `qt6-base-dev`, `qt6-base-dev-tools`, `qt6-connectivity-dev`,
  `qt6-tools-dev`, `qt6-tools-dev-tools`

Внутренние прокси и адрес registry в `.gitlab-ci.yml` относятся к приватной
инфраструктуре; для внешней сборки используйте Docker-образ напрямую.

## Перевод (i18n)

Исходные строки интерфейса написаны на русском языке. CMake собирает
каталог `.ts` через `qt_add_translations`, встраивает `.qm` в ресурс
`:/i18n`, а `main.cpp` загружает подходящий каталог по системной локали.

Файл каталога: `DiscoDiag_ru_RU.ts`. Сейчас он содержит незавершённые
переводы (заготовка), поэтому интерфейс отображается на языке исходных
строк. Для добавления языка:

```bash
lupdate src -ts DiscoDiag_<locale>.ts   # обновить каталог
# заполнить переводы в Qt Linguist
cmake --build build                      # lrelease выполнится автоматически
```

## Примечания по разработке

### Именование файлов

| Тип | Расширение | Пример |
|---|---|---|
| Заголовочные файлы | `.h` | `BtBackend.h` |
| Исходные файлы | `.cpp` | `BtBackend.cpp` |
| Qt Designer | `.ui` | `mainwindow.ui` |
| Qt Translation | `.ts` | `DiscoDiag_ru_RU.ts` |

### Стиль кода (Qt Creator)

- Отступы: **4 пробела**
- Кодировка: **UTF-8**
- Ширина строки: **80 символов**

### Область текущего статуса

**Реализовано и активно в цикле опроса (13 команд):**
- 8 температурных датчиков (охлаждающая жидкость, масло, коробка,
  компрессор, наружный воздух, впуск, раздатка, задний дифференциал)
- Уровень масла (`2203E6`)
- Объём масла (`2203F2`)
- Давление топлива (`22F423`)
- Давление тормозной системы (`222B0D`)
- Уровень топлива (`22F42F`)

**Заглушки:**
- Расширенные параметры (`ExtParamsCommandImpl`) — только заготовка команды

### Известные особенности

1. **Адрес Bluetooth** — по умолчанию `10:21:3E:4A:3E:41`. Диалог
   `RemoteSelector` передаёт выбранный адрес в `ObdService`, значение
   сохраняется в `QSettings`.

2. **Виджет давления масла** — `numPressOil`/`dPressOil` присутствуют в
   UI, но соответствующая команда OBD2 пока не реализована.

3. **Виджеты давления и топлива** — значения `22F423`, `222B0D` и
   `22F42F` отображаются в третьем ряду приборной панели.

4. **Потоки** — `ObdService`, `BtBackend` и `QBluetoothSocket` работают в
   отдельном рабочем потоке (`QThread` + `moveToThread`); UI получает
   результаты через queued-сигналы `updateUI`/`runningChanged`. Задержка
   между командами задаётся одноразовым `QTimer` (100 мс).

5. **Парсинг** — `BtBackend` разбивает поток по `>`, `ObdParser` находит
   маркер `0x62` и не зависит от эха/заголовков. Ответы с несколькими
   ECU/несколькими кадрами пока не объединяются.

6. **Точность** — `calculate()` возвращает `int`; давление тормозной
   системы и объём масла теряют дробную часть.
